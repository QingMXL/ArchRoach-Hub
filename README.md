## 项目简介

**Arch = 建筑学，Roach = 蟑螂。**

建筑人熬大夜、反复改方案，耐造、适应力极强，像蟑螂一样在哪都能扎根活下去。

项目发心，是为建筑学生与设计师搭一个转行互助小站。

整合各路建筑人跨界的真实经历，拆解咱们画图、调研、做方案练出的本事能平移到哪些行业，配套简历 / 作品集的改造思路，还能找到同路转行的前辈请教。

网上转行经验碎得满天飞，与其四处拼凑碎片，不如来这里系统化看清你的职业备选路。

项目会持续迭代更新，不断扩充新赛道、真实转行案例与实用求职干货。

## 开场页

第一次进站会先看到一个开场：两侧是点阵组成的手，中间是站名，一只蟑螂在中间地带爬。

- **方向键**（或 WASD）控制蟑螂移动，朝向跟着走向转
- **点击画面任意位置**，蟑螂会自己爬过去，远处快、临近减速
- 点「点击进入」/ 回车 / Esc → 开场淡出，进入首页
- 每个浏览器会话只出现一次；想重看加 `?intro=1`

![开场页](screenshots/00-opening.png)

点阵手不是图片：用若干旋转椭圆拼出手的轮廓，再逐格采样成点，指尖方向逐渐变稀变淡。所以任意尺寸都清晰，也不用额外资源。

## 现在站里有什么

- **转行方向** —— 每个方向摊开讲清楚：适配度、要不要作品集、准备周期、常见进入路径、要补哪些能力
- **真实案例** —— 匿名但结构统一的转行路径，从契机、能力迁移、材料准备一路讲到面试和最难的部分
- **能力迁移词典** —— 把「场地调研」「方案推演」「多专业协调」翻译成职场听得懂的话，并指向对应岗位
- **前辈咨询** —— 找已经走过这条路的人聊，看得到擅长主题、服务与价格
- **资源库 / 路线图** —— 接受建筑背景的岗位、简历与作品集指南，以及一条六步走的转行路线

内容还在长，方向、案例和前辈都会持续加。

## 关于当前版本

这是一版**可以完整点完的前端原型**，请注意：

- 没有后端和账号系统，站里的方向、案例、前辈、岗位都是写在 `assets/js/data-*.js` 里的示例内容，不是真实的人和岗位
- 预约下单流程是界面演示，不会产生任何真实交易
- 收藏和语言偏好存在浏览器本地，换设备不同步
- 案例封面和前辈头像都是代码画的 SVG 插画，不是照片

真实内容接入、登录与支付会在后续版本补上。

## 技术实现

刻意保持简单，**没有框架、没有构建步骤、没有依赖**：

- 原生 HTML / CSS / JavaScript，hash 路由 + 字符串模板渲染 + 事件委托
- 设计令牌集中在 `assets/css/tokens.css`
- 蟑螂角色的 12 种姿势、45 个图标、案例封面全部是内联 SVG，零外部请求
- 不用 ES Module 与 `fetch`，所以**直接双击 `index.html` 就能打开**

```
index.html          应用外壳：侧栏 + 顶栏 + SVG 雪碧图
assets/css/         tokens / base / layout / components / pages
assets/js/
  i18n.js           中英词典与切换
  data-*.js         内容数据
  ui.js  art.js     渲染原子与插画
  page-*.js         各页面
  app.js            路由、全局搜索、抽屉
docs/               产品 SPEC、设计系统、设计参考图
screenshots/        README 截图
```

## 部署

托管在 Vercel，纯静态：

```bash
npx vercel deploy --prod
```

`vercel.json` 里配了 CSP、HSTS、`X-Content-Type-Options` 等安全响应头；`.vercelignore` 把 `docs/` 与 `screenshots/` 排除在部署产物之外。

## 设计说明

冷灰白工作台底色，蟑螂棕 `#B9632E` 只用在主按钮、Logo 和小面积强调；一级内容用**文件夹卡片**承载，低饱和粉彩只做分类识别。

蟑螂是品牌组件不是表情包 —— 挥手、指路、拿放大镜、抱文件夹、庆祝、戴领带 / 眼镜 / 安全帽…… 用在 Logo、引导、空状态和前辈头像上。完整规范见 [`docs/design-system.md`](docs/design-system.md)，产品定义与内容隐私规则见 [`docs/SPEC_建筑蟑螂互助会_PRD与MVP_v1.0.md`](docs/SPEC_建筑蟑螂互助会_PRD与MVP_v1.0.md)。

内容遵循一条原则：**案例只公开类别与区间**（专业类别、经验区间、准备周期），不公开学校、精确公司与精确薪资；前辈用昵称和角色形象，不用真名和照片。
